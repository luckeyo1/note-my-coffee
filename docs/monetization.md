# 수익화 설계 (Monetization)

퀴즈 결과의 원두 링크를 **어떻게 돈으로 바꾸는가**에 대한 단일 진실 소스.
계측 이벤트 정의는 [`docs/funnel.md`](./funnel.md), 관리자 화면은
[`docs/admin-roadmap.md`](./admin-roadmap.md)에 있다.

> 이 문서는 내부 문서다. `firebase.json`이 `**/*.md`를 호스팅 배포에서 제외하므로
> 공개 사이트에는 올라가지 않는다.
> ⚠️ **단 Cloudflare Pages는 이 ignore 목록을 쓰지 않는다.** `docs/*.md`와 `ADMIN.md`가
> `*.pages.dev`로 공개 서빙되고 있는지 아직 확인되지 않았다 — 확인 후 이 경고를 지운다.

---

## 전제: 지금 병목은 수익화가 아니라 트래픽이다

작성 시점 기준 실사용자 ~2명 / 레시피 ~10건, Play 비공개 테스트는 시작 전이다.
수익 = 트래픽 × 전환 × 마진인데 트래픽이 사실상 0이므로 **어떤 모델을 붙여도 매출은
0에 수렴한다.** 그래서 이 문서의 목적은 모델을 고르는 게 아니라,

1. 리드타임이 긴 **승인 절차를 미리 밟아두고**,
2. 언제 무엇을 켤지 **숫자로 된 게이트를 못박아**,
3. 되돌리기 비싼 결정(광고·구독·데이터 판매)을 **근거가 생길 때까지 미루는** 것이다.

North Star는 그대로 `recipe_saved`다. 수익 지표로 바꾸지 않는다.

## 이미 깔려 있는 것 (다시 만들지 말 것)

제휴 레일은 사실상 완성돼 있다. 승인만 나면 켜진다.

| 자산 | 위치 | 상태 |
|---|---|---|
| 링크 생성 빌더 2개 | `index.html` `kurlySearch` / `naverSearch` | 제휴 딥링크로 **교체만** 하면 됨 |
| 스토어 목록 | `index.html` `STORES` 배열 | 항목 추가 시 링크가 자동 확장 |
| 링크 마크업 | `index.html` `.bean-links` 렌더링 | `STORES`를 순회 — 스토어 추가에 마크업 수정 불필요 |
| 클릭 계측 | `bean_link_click{profile, store, bean_name}` | `store` 파라미터가 자동으로 따라옴 — **추가 계측 코드 불필요** |
| 고지 문구 자리 | `index.html` `.quiz-note` 문단 | 대가성 문구를 여기 덧붙인다 |
| 앱 내 후원 숨김 | `index.html` 인라인 스크립트 | Play 결제 정책 대응 완료 |

현재 프로필 4개 × 원두 3개 × 스토어 2곳 = **링크 24개**. `STORES`에 한 곳을 더하면
36개가 된다.

### 개별 상품 URL 금지 — 이건 규칙이다

한 번 개별 상품 URL(`/goods/1234`, `goodsNo=…`)을 넣었다가 **링크가 통째로 죽었다.**
상품은 품절되고, 상품번호는 재입고 때마다 새로 발급되고, 공동구매 상품은 영구 품절로
남는다. 검색 결과 페이지는 상품이 사라져도 페이지가 죽지 않는다. 제휴 전환 시에도
이 규칙이 우선한다 — 아래 네이버 항목 참고.

## 제휴 프로그램 3곳 — 승인 절차와 우리 적합성

| 프로그램 | 가입 요건 | 승인 | 우리 상황 |
|---|---|---|---|
| **쿠팡 파트너스** | 쿠팡 계정 + 링크를 올릴 채널(웹사이트/앱) 1개 이상. 개인 유형 가능 | 심사 **1~3영업일**, 대부분 통과. **2단계** — 초기 승인 후 누적 판매 15만 원을 넘기면 최종 승인 | ✅ **지금 신청 가능.** 현실적인 첫 수익원 |
| **네이버 쇼핑 커넥트** | 네이버 계정 | **심사 없음** — 약관 동의 즉시 활동 | ⚠️ **스마트스토어 개별 상품 링크만** 발급된다. 위 금지 규칙과 정면 충돌 |
| **컬리 큐레이터** | SNS 팔로워 **1,000명 이상**(1star) / 3만 명(2star). 마이컬리에서 SNS URL 등록 | 채널 심사 | ❌ **현재 자격 미달** — 운영 중인 SNS 채널이 없다 |

### 여기서 나오는 세 가지 결정

1. **컬리는 당분간 순수 검색 링크로 남긴다.** 수익은 안 되지만 사용자에게는 여전히
   유용하다. 팔로워 1,000명은 별도 채널 운영이 선결 과제다.
2. **네이버 커넥트는 보류한다.** 가입은 쉽지만 커넥트 링크는 개별 상품 단위라, 위의
   "링크 사망" 사고를 그대로 다시 부른다. 도입하려면 링크 유효성 점검을 정기 작업으로
   떠안을 각오가 있어야 한다. 지금 규모에서는 손익이 안 맞는다.
3. **쿠팡은 세 번째 스토어로 *추가*한다 — 교체가 아니다.**
   지금 추천 원두는 센터커피·프릳츠·나무사이로·테라로사 같은 **스페셜티 로스터리**다.
   쿠팡에 없거나 재판매만 있는 경우가 많아, 수수료에 맞춰 추천 목록을 쿠팡 재고로
   바꾸면 **추천 신뢰도 — 이 서비스의 유일한 차별점 — 가 깎인다.**
   추가해 두고 `bean_link_click{store}`로 실제 클릭 분포를 본 뒤 판단한다.

## 승인 후 체크리스트 (승인 전에는 절대 미리 하지 말 것)

### 1. 대가성 고지 문구 — 필수

쿠팡 파트너스는 링크·배너 주변에 아래 문구를 요구한다. 공정위 추천·보증 심사지침상
프로그램과 무관하게 필요하다.

```
이 포스팅은 쿠팡 파트너스 활동의 일환으로, 이에 따른 일정액의 수수료를 제공받습니다.
```

삽입 위치는 이미 있다 — `index.html`의 `.quiz-note` 문단에 한 줄 덧붙인다.

> ⚠️ **가입 전에 넣으면 안 된다.** 사실이 아닌 고지가 되고, 그 자체가 표시광고법
> 위반 소지가 된다. 승인 메일을 받은 뒤에 넣는다.

### 2. 모바일 앱 활동 신고

쿠팡 파트너스는 앱에서 활동할 경우 **앱 URL과 활동 스크린샷 등록**을 요구한다.
Play 출시 후 스토어 URL이 나오면 파트너스 콘솔에 등록한다.

단, `manifest.json`의 `start_url`이 `./app.html?source=pwa`라 **앱을 열면 랜딩(퀴즈)이
아니라 기록 화면이 뜬다.** 즉 현재 제휴 노출은 사실상 웹 전용이다. 앱 안으로 끌어오는
개편은 웹 실적을 본 뒤에 판단한다.

### 3. 정산 조건

최소 지급액 1만 원. 발생월 말일 기준 **다다음 달 15일** 지급.

---

## 정책 확인 — 지금은 문제 없음, 단 조건부

- **Play**: 원두는 **실물 상품**이라 외부 링크·외부 결제가 허용된다. 디지털 재화(후원)는
  이미 앱에서 숨김 처리돼 있다. → **추가 조치 불필요.**
- **개인정보**: 제휴 링크는 아웃바운드 링크일 뿐이고 URL 파라미터에 개인정보가 실리지
  않는다. → `privacy.html`("정보를 판매하거나 광고 목적으로 제3자에게 제공하지
  않습니다")과 이미 제출한 Play 데이터 보안 양식(제3자 공유 = 아니요)을 **고치지 않아도
  된다.**
- ⚠️ **단, 제휴사가 사이트에 추적 스크립트·픽셀 설치를 요구하면** 그 순간 제3자 추적이
  된다. 그때는 `privacy.html` 개정 + Play 데이터 보안 양식 갱신이 **선행**돼야 한다.
  신청 화면에서 이 요구가 있는지 먼저 확인한다.

## 판단 게이트 (초안 — 실측 후 재보정)

지표는 전부 GA4에 이미 들어온다. 새 계측 코드는 필요 없다.

| 무엇을 | 언제 | 되돌리기 비용 |
|---|---|---|
| **제휴를 켠다** | 승인 나는 즉시 (게이트 없음) | **낮음** — 빌더를 되돌리면 끝 |
| **제휴에 투자한다**<br>(원두 큐레이션 확대·전용 페이지) | 월 `quiz_complete` ≥ 100건 **그리고**<br>`bean_link_click / quiz_complete` ≥ 15% | 낮음 |
| **유료 기능·구독을 검토한다** | 2주 연속 `recipe_saved` 사용자 ≥ 100명 | **중간** — 디지털 재화라 Play 결제 필수. 가격·게이팅은 되돌려도 신뢰가 남지 않는다 |
| **B2B 로스터리 리포트를 검토한다** | 월 활성 기록자 ≥ 300명 **그리고**<br>단일 로스터리 원두 기록 ≥ 500건 | **높음** — 익명 집계라도 "제3자 제공"에 걸릴 소지가 있다. 개인정보처리방침 개정 + 별도 동의 흐름 + Play 양식 갱신이 **필수**. 지금 약속을 깬 채로 진행하면 안 된다 |

B2B의 전제인 원두명 정규화는 이미 상당 부분 해결돼 있다 — `main.js`가 '개봉 중' 선택
시 최근 원두 칩을 띄우고 직전 기록을 prefill한다. (`storage.js`의 `getRecentBeans()`는
이 구현에 밀린 **미사용 코드**다.)

## 지금 하지 않는 것

- **광고 SDK** — 현 개인정보처리방침·Play 양식으로는 불가. 둘 다 고쳐야 한다.
- **구독 게이팅 / 인앱 결제** — 유지율 근거 없음.
- **데이터 판매** — 위 게이트 미달, 되돌리기 비용 최대.
- **네이버 커넥트** — 개별 상품 링크 문제.
